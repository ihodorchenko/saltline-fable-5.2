# Saltline — подготовка к расширению

Предложение для ветки **`exp/foundation`**. Здесь ничего не мержится в `dev`/`main` и ничего не пушится без отдельной команды владельца.

**Состояние на момент создания ветки**

- `main` = `09c5177` (исходное зеркало), `dev` = `ddfbf83` (docs + ремапы управления), всего 7 коммитов.
- `index.html` = 1 423 592 байта, sha256 `2599361f…`; игра работает, управление актуальное (бег `X`, огонь `Shift`/ЛКМ, прицел `E`/ПКМ, взаимодействие `F`, melee `V`).
- В репозитории есть `README.md`, `index.html`, `docs/OVERVIEW.md`; нет `package.json`, сборки, тестов, CI, лицензии и source map.

---

## 1. Цель этапа

Сделать так, чтобы новую механику, уровень или тему можно было добавлять **без ручной правки минифицированного файла на 1.4 МБ**, при этом:

- текущая игра остаётся играбельной и визуально прежней;
- движок (рендер, материалы, звук, UI, ввод) можно переиспользовать в другом режиме/игре;
- изменения проверяются автоматически, а не «на глаз»;
- паркур-прототип или новая тематика начинаются с чистой базы, а не с ещё одного форка однострочника.

## 2. Что мешает сейчас

| Проблема | Почему мешает | Что делаем |
|---|---|---|
| Один минифицированный `index.html` | нет модулей, конфликты при правках, невозможно ревьюить | сборка + `src/`, один файл — только артефакт сборки |
| Нет тестов и CI | страшно менять физику/рендер, регрессии ловятся глазами | unit-тесты + headless-smoke + скриншоты |
| Движок и игра связаны | нельзя взять рендер/звук для новой темы | `src/engine` с устойчивым API, `src/game` отдельно |
| AABB-физика и ровная земля | паркур, наклоны и стены невозможны | capsule-контроллер, запросы к стенам/уступам |
| Процедурный контент | новый арт и уровни дороги | формат уровней + пайплайн ассетов + fallback |
| Управление захардкожено | каждый ремап — правка кода и UI | таблица биндингов + перепривязка |
| Нет лицензии/NOTICE | юридическая неопределённость при публикации | `NOTICE`, решение по лицензии только для своего кода |
| Нет `package.json` | нельзя подключить линтер, тесты, сборку | Node-проект и lock-файл |

## 3. Принципы

1. **Игра playable на каждом шаге.** Не бывает коммита, после которого demo не запускается.
2. **Сначала паритет, потом изменения.** Выносим код в модули, не меняя поведение; проверяем скриншотами и smoke-тестом.
3. **Маленькие коммиты в `exp/*`.** Один модуль/одна механика за раз.
4. **Ничего чужого.** Для новой темы — только оригинальные или явно лицензированные ассеты; никаких файлов Mirror's Edge.
5. **Сначала измеряем.** Любая оптимизация — после профиля и бюджета.
6. **Никаких merge/push в `dev`/`main` без команды.** Ветка `exp/foundation` живёт отдельно.

## 4. Целевая структура

```
src/
  engine/
    render/        # рендерер, пост, тени, качество
    materials/     # процедурные материалы, декали, надписи
    audio/         # синтез, шины, реверб, музыка
    fx/            # частицы, трассеры, дым, дождь
    ui/            # HUD, меню, настройки, подсказки
    input/         # действия, биндинги, мышь/тач/геймпад
    physics/       # капсула, мир, запросы, навигация
    core/          # время, события, RNG, настройки, утилиты
  game/
    saltline/      # текущая игра: уровни, режимы, правила
    modes/         # title / campaign / tutorial / showcase / bench
  prototypes/
    parkour/       # лаборатория движения (серая крыша)
  levels/
    *.json         # описание геометрии, триггеров, спавнов
  assets/          # только исходники/манифесты, без бинарного мусора
tools/
  smoke/           # headless-проверка и скриншоты
  perf/            # замеры кадра
docs/              # OVERVIEW, EXPANSION, ARCHITECTURE, ADR
dist/              # собранный один файл (не коммитим или коммитим по решению)
```

Точка входа для публикации остаётся одной: `dist/index.html`. Для GitHub Pages позже решим, публиковать его из корня или из `/docs`; `main` сейчас не трогаем.

## 5. Фазы

### P0 — гигиена и базовая проверка (1–2 дня)

- [ ] `.gitignore`: `node_modules/`, `dist/`, `.DS_Store`, скриншоты, логи.
- [ ] `.editorconfig`, `.nvmrc`, фиксированный Node LTS.
- [ ] `NOTICE.md`: авторство исходной игры, статус форка, что именно добавлено нами. **Лицензию на весь репозиторий не ставим**, пока не ясно правообладание исходного кода; лицензию на свои модули оформляем отдельно после решения.
- [ ] Smoke-скрипт: поднять `http.server`, открыть headless-браузер, проверить `window.__errors`, снять скриншот титула и игрового старта.
- [ ] Зафиксировать baseline: fingerprint `index.html`, два скриншота, время загрузки, `__stats()`.
- [ ] CI-скелет (GitHub Actions): install → lint → build → smoke (пока может быть красным/ручным).

**Готово, когда:** smoke запускается одной командой и падает при JS-ошибке или белом экране.

### P1 — сборка и разделение кода (1–2 недели)

- [ ] `package.json` + lock-файл; `npm` или `pnpm` — по решению.
- [ ] Vite (dev-сервер + HMR) и сборка в один файл (`vite-plugin-singlefile` или собственный esbuild-плагин).
- [ ] Вынести JS из `index.html` в `src/` по модулям; CSS — в `src/ui/styles.css`.
- [ ] Сохранить однофайловый артефакт и source map для разработки.
- [ ] ESLint + Prettier; без фанатизма, но с единым стилем.
- [ ] **Паритет:** сборка запускается, титул/геймплей совпадают по скриншотам с допуском; `?show=…` работает.

**Готово, когда:** `npm run dev` даёт игру с HMR, `npm run build` — один `dist/index.html`, паритет подтверждён.

### P2 — движок, режимы, ввод (1–2 недели)

- [ ] `engine`-модули с явным API: `createRenderer`, `createMaterials`, `createAudio`, `createFX`, `createUI`, `createInput`, `createPhysics`.
- [ ] Реестр режимов: `title`, `campaign`, `tutorial`, `showcase`, `bench`; старые query-параметры остаются алиасами.
- [ ] Единый event bus, время, детерминированный RNG.
- [ ] Биндинги действий отдельно от клавиш: таблица по умолчанию, сохранение в `localStorage`, позже — UI перепривязки.
- [ ] Схема настроек с версией и миграциями.
- [ ] HUD-подсказки берут клавишу из биндингов, а не из хардкода.

**Готово, когда:** Saltline-режим работает через `game/saltline` и не импортирует внутренности движка напрямую.

### P3 — физика и паркур (2–4 недели)

- [ ] Capsule-контроллер: наклоны, шаг, прилипание к земле, потолки, движущиеся платформы.
- [ ] Запросы: `raycast`, `sphereCast`, `wallNormal`, `ledgeAt`, `groundAt`.
- [ ] Состояния: `run`, `jump`, `vault`, `mantle`, `wallRun`, `wallClimb`, `slide`, `roll`, `balance`; буферизация ввода.
- [ ] Камера: крен, FOV от скорости, просадка при приземлении, тряска.
- [ ] `prototypes/parkour`: серая крыша, 6 станций, чекпоинты, таймер.
- [ ] Тесты: коллизии, уступы, стены, стабильность при разных `dt`.
- [ ] Спайк Rapier: сравнить с собственным контроллером по размеру, детерминизму, удобству; решение записать в ADR.

**Готово, когда:** серый маршрут проходится без застреваний, `dt` 30/60/120 даёт одинаковый результат, туториал можно играть.

### P4 — уровни, контент, производительность (2–4 недели)

- [ ] Формат уровня JSON: платформы, стены, уступы, триггеры, подсказки, спавны, чекпоинты.
- [ ] Загрузчик + debug-камера + hot reload в dev-режиме.
- [ ] Ассеты: процедурная генерация остаётся fallback; появляется кэш/предгенерация/worker, позже — GLTF для сложных пропсов.
- [ ] Бюджеты: draw calls, треугольники, память, время кадра; `?stats`/`?bench` и CI-замер.
- [ ] Аудио-пайплайн: шаги/ветер/приземления из синтеза, музыкальный луп, громкости по шинам.
- [ ] Доступность: перепривязка, субтитры, reduced motion, контраст.

### P5 — вертикальный срез / решение о теме (2–4 недели+)

- Вариант A: **Mirror's Edge-подобный туториал** — оригинальная крыша, 5–8 минут, 6 механик, подсказки, чекпоинты, таймер, без врагов и сюжета.
- Вариант B: **новая тематика** на том же движке — одна локация, одна ключевая механика, 10 минут.
- Критерий: играбельный срез, который можно сравнить с референсом и решить, масштабировать или остановиться.

## 6. Инструменты — рекомендация

- **Node LTS + npm/pnpm**; lock-файл обязателен.
- **Vite** для dev/HMR + single-file сборка. Если single-file плагин окажется капризным — fallback на esbuild-скрипт.
- **JavaScript + JSDoc + ESLint**, без полной миграции на TypeScript. TS — только для новых модулей, если команда захочет; миграция минифицированного кода всё равно невозможна.
- **Vitest** для unit-тестов, **Playwright** для headless-smoke и скриншотов.
- **GitHub Actions** для CI; кэш npm и Playwright-браузера.

## 7. Тесты и паритет

- Unit: RNG, математика, биндинги, схема настроек, физические запросы, A*.
- Smoke: загрузка без `__errors`, титул, старт игры, `?show=level`, `?show=weapon`.
- Golden screenshots: фиксированные `?seed`, `?cam`, `?q=low`, допуск по пикселям; сравнивать до/после рефакторинга.
- Perf: JSON с draw calls/tris/временем кадра; хранить историю.
- Детерминизм: все процедурные генераторы — от seed; тесты не должны зависеть от реального времени.

## 8. Что не делаем

- Не переписываем всё сразу и не переезжаем на UE5/Godot.
- Не тащим ассеты, музыку, тексты и уровни Mirror's Edge.
- Не добавляем лицензию на чужой код без прав.
- Не оптимизируем рендер до появления бюджета и замеров.
- Не мержим и не пушим `dev`/`main` без команды.

## 9. Решения, которые нужны от владельца

1. **Ветка и правила:** `exp/foundation` — ок? Нужны ли отдельные `exp/*` под каждую механику?
2. **Сборка:** Vite или esbuild; npm или pnpm.
3. **Язык:** JS + JSDoc или TS для новых модулей.
4. **Лицензия/NOTICE:** что можно писать про исходный код и что лицензируем у себя.
5. **Путь прототипа:** отдельный `prototype/parkour` или форк Saltline-режима.
6. **Цель:** браузер/десктоп Chrome? Нужна ли мобилка? Какой минимальный FPS.
7. **Тема:** идём в Mirror's Edge-подобный туториал или сначала foundation и новая тема.
8. **CI:** можно ли включить GitHub Actions и хранить там скриншоты.

## 10. Первые шаги после согласования

1. P0: `.gitignore`, `.editorconfig`, smoke-скрипт, `NOTICE`.
2. P1-спайк: вынести **один** небольшой модуль (например, биндинги ввода) в `src/`, собрать single-file и доказать паритет.
3. Если паритет есть — выносить остальное по модулям, начиная с `input` → `ui` → `audio` → `materials` → `render` → `physics`.
4. P3: серая лаборатория паркура.
5. P5: решение по туториалу/теме.

## 11. Оценка

| Этап | Результат | Оценка |
|---|---|---|
| P0 | правила, smoke, NOTICE, baseline | 1–2 дня |
| P1 | сборка, `src/`, паритет | 1–2 недели |
| P2 | engine API, режимы, биндинги | 1–2 недели |
| P3 | капсула + паркур-лаборатория | 2–4 недели |
| P4 | уровни, контент, perf | 2–4 недели |
| P5 | туториал/новая тема | 2–6 недель |

Это оценка для работы «человек + агент» с регулярными плейтестами; без плейтестов сроки по P3/P5 не имеют смысла.

## 12. Критерий успеха foundation

- `npm run dev` — игра с HMR; `npm run build` — один файл.
- `npm test` и `npm run smoke` зелёные; CI повторяет это.
- Игра визуально и поведенчески не хуже текущей.
- Новый режим/уровень добавляется без правки движка.
- Паркур-лаборатория запускается и проходится.
- Документация и биндинги не расходятся с кодом.
