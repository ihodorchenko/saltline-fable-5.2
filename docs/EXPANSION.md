# Saltline — стратегия расширения

Ветка **`exp/foundation`**. Правило: в `dev` и `main` ничего не мержим и не пушим без отдельной команды владельца.

**Снимок на момент создания ветки**

- `main` = `09c5177` (исходное зеркало), `dev` = `ddfbf83`; всего 7 коммитов.
- `index.html` = 1 423 592 байта, sha256 `2599361f…`.
- Управление: бег `X`, огонь `Shift`/ЛКМ, прицел `E`/ПКМ, взаимодействие `F`, melee `V`; `Q` не назначена; `Enter` на титуле запускает игру.
- Есть `README.md`, `index.html`, `docs/OVERVIEW.md`; нет `package.json`, сборки, тестов, CI, лицензии и source map.

---

## 0. Стратегия в двух словах

| | Фаза 1 — `exp/foundation` | Фаза 2 — отдельная ветка позже |
|---|---|---|
| Что делаем | приводим в порядок **то, что уже есть** | делаем **новый проект/тему** |
| Цель | удобно работать, тестировать и переиспользовать | паркур, новая физика, уровни, арт |
| Поведение игры | **не меняется** | меняется/новое |
| Результат | чистая база + референс для других проектов | вертикальный срез/прототип |

Фаза 2 начинается только после приёмки Фазы 1 и отдельной команды. Ветку Фазы 2 создаём отдельно; в неё переносим/копируем фундамент, а не сливаем её обратно в `exp/foundation`.

## 1. Правила работы

1. `main` — релиз/зеркало, `dev` — интеграция, `exp/*` — эксперименты.
2. Игра остаётся играбельной на каждом коммите Фазы 1.
3. Фаза 1 не добавляет геймплей: ни паркура, ни новых уровней, ни новой темы.
4. Сначала паритет (вынесли код — поведение и картинка те же), потом улучшения.
5. Маленькие коммиты; один модуль/один шаг за раз.
6. Никаких чужих ассетов (Mirror's Edge и т. п.).
7. Никаких merge/push в `dev`/`main` без команды.

## 2. Фаза 1 — «удобно работать с тем, что есть»

### 2.1 Цель

Превратить однофайловый минифицированный билд в **сопровождаемый проект**, не меняя саму игру:

- сборка из исходников в один файл;
- понятная структура `engine / game / modes`;
- тесты, smoke, CI;
- документация и ADR;
- биндинги ввода и настройки без хардкода;
- baseline производительности.

Дополнительный результат: **референс**, который можно взять в другой проект — движок, структура, инструменты, документация.

### 2.2 Границы

**Входит в Фазу 1**

- `.gitignore`, `.editorconfig`, `NOTICE`, решение по лицензии нашего кода.
- `package.json`, сборка, dev-сервер, single-file output, source maps.
- Вынос кода в `src/` без изменения поведения.
- Разделение `src/engine` и `src/game/saltline`, реестр режимов.
- Таблица биндингов и схема настроек (текущие дефолты сохраняются).
- Unit-тесты, headless-smoke, golden-скриншоты, CI, perf-baseline.
- `docs/ARCHITECTURE.md`, `CONTRIBUTING`, ADR, инструкция «как переиспользовать».
- Опционально: пустой/template-режим, который поднимает движок с минимальной сценой.

**Не входит (уходит в Фазу 2)**

- Capsule-физика, наклоны, стены, уступы.
- Паркур-контроллер и его состояния.
- Новые уровни, редактор уровней, формат контента.
- Новая тема, арт, музыка, озвучка.
- Туториал Mirror's Edge-подобного типа.
- Любые изменения геймплея, баланса и управления по существу.

### 2.4 Критерии готовности Фазы 1

- `npm run dev` запускает игру с HMR; `npm run build` собирает один файл.
- Игра визуально и поведенчески не хуже текущей; управление прежнее.
- `npm test` и `npm run smoke` зелёные; CI повторяет.
- Новый режим/модуль добавляется без правки движка.
- Документация описывает границы и переиспользование.
- Ветка `exp/foundation` не влияет на `dev`/`main`.

### 2.5 Что получаем как референс

- `src/engine` с документированным API и без Saltline-специфичных имён.
- `src/game/saltline` как пример игры на этом движке.
- `tools/smoke.sh` и CI-конфиг, переносимые в другой проект.
- `docs/ARCHITECTURE.md` + чек-лист «как начать новый проект на этом фундаменте».
- Опционально — пустой `template`-режим: движок, земля, камера, без геймплея.

## 3. Фаза 2 — новый проект (отдельная ветка, позже)

**Когда:** Фаза 1 принята, владелец дал команду, создана отдельная ветка (например, `project/parkour` или `project/<theme>`).

**Что туда уходит:**

- capsule-физика: наклоны, стены, уступы, движущиеся платформы;
- паркур: `vault`, `mantle`, `wall-run`, `wall-climb`, `slide`, `roll`, `balance`;
- камера паркура: крен, FOV, приземления;
- уровни/формат контента/редактор;
- арт, музыка, звук, UI новой темы;
- вертикальный срез: туториал Mirror's Edge-подобного типа или другая тема.

**Правила Фазы 2:**

- не менять `exp/foundation` под нужды новой игры;
- общие багфиксы движка — отдельными коммитами/ветками и только по команде;
- новая игра не обязана сохранять поведение Saltline, но обязана использовать engine API;
- ассеты — только оригинальные/лицензированные; никаких файлов Mirror's Edge.

## 4. Целевая структура

```
src/
  engine/        # Фаза 1: render, materials, audio, fx, ui, input, physics, core
  game/
    saltline/    # Фаза 1: текущая игра
  modes/         # Фаза 1: title / campaign / showcase / bench (+ template)
  # Фаза 2 добавляет:
  # prototypes/, levels/, assets/, game/<new-theme>/
tools/           # smoke, perf, генераторы
docs/            # OVERVIEW, EXPANSION, ARCHITECTURE, ADR
dist/            # собранный один файл
```

## 5. Инструменты — рекомендация

- **Node 22 LTS** (22.23.5) через `Brewfile`/`.nvmrc`; npm 10.9.9; npm-манифест — `package.json` + `package-lock.json`.
- **Vite 7.3.8** + `vite-plugin-singlefile` для dev/HMR и сборки в один файл; esbuild и Rollup идут транзитивно.
- **HMR** работает через Vite; изменения огромного `src/game/main.js` могут вызывать полную перезагрузку, это нормально для spike.
- **JavaScript + JSDoc + ESLint**; TypeScript — только для новых модулей, если команда решит. Полная миграция минифицированного кода не имеет смысла.
- **Vitest** (unit), **Playwright** (headless, скриншоты).
- **GitHub Actions** (если владелец разрешит).

## 6. Тесты и паритет

- Unit: RNG, математика, биндинги, схема настроек, физические запросы, A*.
- Smoke: загрузка без `__errors`, титул, старт, `?show=level`, `?show=weapon`.
- Golden screenshots: фиксированные `seed/cam/q`, допуск; сравнение до/после рефакторинга.
- Perf: draw calls, tris, frame time; хранить JSON по коммитам.
- Детерминизм: всё процедурное — от seed; тесты не зависят от реального времени.

## 7. Риски и что не делаем

- **Регрессии при выносе кода** → паритет-тесты и golden screenshots.
- **Расползание Фазы 2 в Фазу 1** → явный запрет на новую физику/геймплей.
- **Инструменты съедают время** → сначала маленький spike: один модуль, сборка, паритет.
- **Лицензия** → `NOTICE`, без лицензии на чужой код.
- **Node/CI** → Node 22 LTS локально и в CI; версии фиксированы `Brewfile`/`.nvmrc`/lock-файлом; кэш браузера.
- **Не делаем:** переезд на UE5/Godot, полную миграцию на TS, копирование ассетов, «большой рефакторинг одним коммитом».

## 8. Решения, которые нужны от владельца

1. **Пакетный менеджер:** npm 10.9.9 зафиксирован (`packageManager`), pnpm не нужен.
2. **Сборка:** Vite 7.3.8 выбран и работает на Node 22.23.5; fallback-сборка на esbuild удалена.
3. **Язык:** JS + JSDoc или TS для новых модулей.
4. **Лицензия/NOTICE:** что пишем про исходный код; лицензируем ли свои модули.
5. **CI:** можно ли включить GitHub Actions.
6. **Rebinding UI:** делать в Фазе 1 или только таблицу биндингов, а UI — позже.
7. **Template-режим:** нужен ли пустой режим для референса.
8. **Цель:** только desktop Chrome или ещё мобилка; минимальный FPS.
9. **Старт Фазы 2:** когда считаем Фазу 1 принятой.
